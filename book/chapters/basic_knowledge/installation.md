### 1.2. Установка

Основные способы установки указаны [здесь](https://www.haskell.org/ghcup/install). Можно добавить, что для GUI-операционок можно предварительно установить Visual Studio Code (не путать c Visual Studio) и воспользоваться расширениями Haskell и Haskell Run.

Ожидается, что после этого у вас доступна команда ghci, которая запускает интерактивную среду Haskell.

Её можно использовать для построчного выполнения кода. Введите в командную строку `ghci`. Ожидается, что вы увидите что-то в духе:

```shell
GHCi, version 9.10.3: https://www.haskell.org/ghc/  :? for help
ghci> 
```

Введите `2+2` и нажмите `Enter`. В результате выведется `4`.

Проверим стандартные функции. Введите `even 6`. В результате получится `True` (поскольку 6 это чётное число). Так же можно убедиться, что `even 1` выдаёт `False`.

Проверим функцию `isLengthEven` из предыдущего раздела. Введите `isLengthEven s = even (length s)` и нажмите `Enter`. Ожидается, что команда выполнится без ошибок и вообще любого вывода. После этого среда будет знать о наличии функции `isLengthEven`. Соответственно, её можно будет вызывать. Обращу внимание, что после перезапуска все знания о функциях будут удалены.

Убедитесь, что `isLengthEven ""` выведет `True`. Можете проверить и то, что `incorrectFunction s = (isLengthEven s) + 2` не получится выполнить. 

```shell
ghci> incorrectFunction s = (isLengthEven s) + 2 
<interactive>:23:40: error: [GHC-39999]
    * Could not deduce `Num Bool' arising from a use of `+'
      from the context: Foldable t
        bound by the inferred type of
                   incorrectFunction :: Foldable t => t a -> Bool
        at <interactive>:23:1-42
    * In the expression: (isLengthEven s) + 2
      In an equation for `incorrectFunction':
          incorrectFunction s = (isLengthEven s) + 2
```

Как читать эти ошибки, расскажем дальше по документу.

Пока проверим последний пример из предыдущего раздела. Введите строки `x::Integer` и `x = 2`. Вы увидите, что проблемы будут при первой же строчке:

```shell
ghci> x::Integer
<interactive>:30:1: error: [GHC-88464]
    Variable not in scope: x :: Integer
```

Проблема возникает потому, что каждая вводимая команда в ghci должна либо определением новой функции/переменной, либо выполнением некоторого действия. `x::Integer` не является ни чем из них, это просто объявление того, что будет некоторое `x` с типом `Integer`.

Вариантов, как это обойти, несколько:

* Ввести команду `x::Integer = 2`. Так мы явно определеяем, что `x` равно 2 и что у `x` тип `Integer`.
* Ввести исходные команды через точку с запятой: `x::Integer; x = 2`.
* Ввести многострочные команды через специальные команды `:{` и `:}`. Первая переводит ghci в режим ввода многострочной команды, дальше можно вводить команды как были, и после ввести команду `:}`, которая выполнит введеные команды и вернет ghci в режим ввода однострочных комманды.

```shell
ghci> x::Integer
ghci> :{
ghci| x::Integer
ghci| x = 2
ghci| :}
ghci> x
2
```

### Тесты для самопроверки

#### Определите согласно примеру из предыдущего раздела значение `y` типа `Double`, равное 2.1. Убедитесь, что `f = (x == y) невалидная команда. Почему она невалидная?

<details>
<summary><b>Ответ</b></summary>
Потому что `x` и `y` имеют разные типы, и их нельзя сравнивать на равенство.
</details>

#### Предположим, что у нас есть функция `integerToDouble`, принимающая аргумент типа `Integer` и возвращающее эквивалентное значение типа `Double`. Как тогда может выглядеть валидное определение `f`?

<details>
<summary><b>Ответ</b></summary>
Можно сделать например так `f = ((integerToDouble x) == y)`.
</details>
