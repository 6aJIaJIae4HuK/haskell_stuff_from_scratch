### Что такое Haskell?

Это язык программирования. :)

Рассмотрим основные свойства языка. После разберем, что каждое из них означает:

* _Haskell является функциональным_.
* _Haskell является компилируемым_.
* _Haskell является языком со статической типизацией_.
* _Haskell является языком с сильной типизацией_.
* _Haskell является строго чистым_.

#### Функциональность Haskell.

Это фундаментальное свойство, поэтому поподробнее. Для таких языков основная единица кода — это функция. Под функцией здесь понимается именно функция в математическом смысле — принимает ноль или более значений на вход и возвращает результат. Haskell предоставляет богатую стандартную библиотеку функций. Программист может определять новые функции как композиции уже существующих функций (в том числе и из определённых ранее).

Функции определяются интуитивным образом — `<имя функции> <аргумент1> <аргумент2> ... = <результат>`. В качестве результата здесь можно указывать вызовы существующих функций в том же формате `<имя функции> <значение1> <значение2> ...`. 

Пример функции, которая проверяет, является ли длина строки чётной: 

```haskell

-- even x   стандартная функция, которая принимает целое число x и возвращает True, если оно чётное или False, если нечётное.

-- length s стандартная функция, которая принимает список (строка есть список символов) и возвращает её длину

isLengthEven s = even (length s)  -- вызываем length s и передаём её результат в качестве аргумента `even`
```

Причем в качестве аргументов можно передавать и сами функции.

Соответственно `isLengthEven "abc"` вернёт `False`, а `isLengthEven ""` вернёт `True`. Замечу, что это лишь базовый способ определять новые функции. По ходу документа будут показаны другие способы. В целом, любая программа на Haskell это сложная функция.

Помимо функциональных языков существуют императивные языки. Для них основная единица кода это изменяемая переменная. И программа есть набор инструкций, которые читают/изменяют переменные. Императивные языки противопоставляются функциональным. Про первые можно думать в контексте "как сделать", про вторые — "что сделать".

#### Компилируемость языка.

Код на Haskell преобразовывается специальным инструментарием в набор машинных инструкций, который будет понятен компьютеру. На выходе получается готовый исполняемый файл (запускаемая конечная программа) или объектный файл (библиотека, которую можно подключать к другим исполняемым файлам) в зависимости от кода.

Компилируемым языкам противопостовляются интерпретируемые языки. Это языки, для которых есть специальная программа (интерпретатор), которая исполняет команды по очереди. Интерпретатор уже скомпилированная программа, предоставляемая экосистемой языка. Как правило, на компилируемых языках получаются более высокопроизводительные программы (в первую очередь из-за того, что компилятор знает о всем коде и может делать более агрессивные оптимизации, а интерпретатор знает только о конкретной команде, которую исполняет в данный момент).

#### Статическая типизация.

В языках программирования так или иначе присутствует понятие _типа данных_. Под ним можно рассматривать именнованное множество значений и операций над этими значениями. Для примера, тип "строка" — это последовательность (возможно пустая) символов и над ней практически всюду определена операция взятия длины. Далее для языка программирования вводится понятие _типизации_ — как набора правил, как связываются между собой значения и типы и как определять, можно ли применять операцию ко значению(ям). Если коде программы попробовать к строке прибавить число 4, то как и в какой момент будет принято решение, что это некорректная операция?

В Haskell принята т.н. _статическая типизация_. Каждому значению в коде на этапе компиляции будет сопоставлен некий тип. И если выяснится, что в коде есть применение недопустимой для этого типа операции (передача в функцию, которая ожидает аргумент другого типа или вызов функции, которая не определена для этого типа). То программа не скомпилируется и программист увидит соответствующую ошибку.

```haskell
isLengthEven s = even (length s)

-- incorrectFunction s = (isLengthEven s) + 2  Не скомпилируется, т.к. isLengthEven s это значение True или False, а операция + для True и целого числа не определена
```

Альтернативой для статической типизации является _динамическая типизация_. Тут правила такие, что тип у значения определяется непосредственно во время исполнения программы. Как следтствие, ошибки, связанные с некорректными операциями, проявят себя только во время исполнения.

#### Сильная типизация.

Сильная типизация подразумевает сильный набор правил касательно того, можно ли делать попытки неявного преобразования значений к правильным типам. Рассмотрим пример выше. Там код не скомпилируется из-за того, что есть попытка сложения True/False с двойкой. Сильная типизация говорит, что попыток воспринимать True/False как число или двойку как True или False делать не надо. Будь Haskell язык со слабой типизацией, то код бы скомпиллировался бы, и incorrectFunction была бы вполне валидной функцией, просто с неочевидным принципом работы. Еще пример сильной типизации тут: 

```haskell

x::Integer  -- объявляем значение x с типом Integer (произвольное целое число)
x = 2

y::Double   -- объявляем значение y с типом Double (вещественное число)
y = 2.5

-- f = (x == y) (проверка на равенство) тут будет невалидной операцией, потому что x и y имеют разные типы, а сравнение определенно только для значений одного типа

```

Обычно к языкам с сильной типизации относят и языки, которые разрешают складывать целые и дробные числа. Потому что это ж валидно так делать, почему это должно не работать? Просто Haskell тут очень сильно типизирован (термин не очень, но другого не знаю).

#### Строгая чистота.

Вот добрались до важнейшего свойства Haskell. В программировании присутствует понятие _побочных эффектов_. Это всё, что так или иначе меняет окружение программы. Для примеров:

* Запись в файл
* Обработка ввода с клавиатуры
* Отображение на экран
* Изменение значения, глобального для программы (в Haskell таких нету, но обычно такое присутствует)
* Отправка/приём данных по сети

Если в функции есть побочные эффекты, то результат функции зависит от внешних по отношению к коду факторов. К примеру, если есть функция вида "подожди, пока пользователь введёт число и распарсь его", то результат такой функции будет зависеть от того, что будет вводить пользователь. Функция называется _чистой_, если у неё нету побочных эффектов. Определённые ранее функции являются такими и зависят только от своих аргументов. В противовес ставятся _грязные_ функции.

Основная идея функциональных языков в том, что надо по минимуму использовать грязные функции. Такой подход позволяет с одной стороны предоставлять гарантии компилятору, на основе которых можно делать оптимизации програм. А с другой стороны — уменьшает число потенциальных ошибок программиста.

Haskell в этом плане ушёл дальше и его концепция это "все функции являются чистыми" (исключения конечно есть, но о них дальше). Читатель может спросить "То есть там нельзя запрограммировать обработку пользовательского входа? А зачем тогда это всё?". Ответ: можно. Как именно это работает, будет разобрано в главе про IO.

#### Верно ли, что у любой функции есть некоторый тип?
- Да
- Нет

<details>
<summary><b>Ответ</b></summary>
Т.к. функция это тоже значение, которое можно передавать в функции, то у любой функции всегда есть конкретный тип.

#### В примере с сильной типизации есть строка `f = (x == y)`. Будь одинаковые типы у значений `x` и `y`, чем бы конкретно являлось `f`?

<details>
<summary><b>Ответ</b></summary>

`f = (x == y)` подходит под синтаксис `<имя функции> <аргумент1> <аргумент2> ... = <результат>`, так что `f` тут является функцией без аргументов, чьё значение это `True` или `False`, в зависимости от значений `x` и `y`.
</details>
