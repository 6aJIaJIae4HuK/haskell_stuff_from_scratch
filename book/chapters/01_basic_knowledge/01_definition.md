### 1.1. Что такое Haskell?

Это язык программирования. :)

Рассмотрим основные свойства языка. После разберем, что каждое из них означает:

* _Haskell является функциональным_.
* _Haskell является компилируемым_.
* _Haskell является языком со статической типизацией_.
* _Haskell является языком с сильной типизацией_.
* _Haskell является ленивым_.
* _Haskell является чистым_.

#### Функциональность Haskell.

Это фундаментальное свойство, поэтому поподробнее. Для таких языков основная единица кода — это функция. Под функцией здесь понимается функция в математическом смысле — преобразование аргументов в результат. Точное определение функции для Haskell будет дано во второй главе. В рамках функционального программирования сейчас важно осознать свойства, к которым стремятся при написании программ:

* Для функции существует определение того, как получить единственно возможный результат, который зависит только от аргументов (детерминированность).
* Вычисление функции не меняет внешний мир (отсутствие побочных эффектов). Для примера — запись в файл это побочный эффект. Изменение глобального состояния программы, к которому можно обращаться, — это тоже побочный эффект.

В совокупности они определяют свойство _чистоты_ функции. Из чистоты функции следует следующее критичное свойство: т.к. для чистой функции есть единственный результат, не зависящий от внешнего мира, и вычисление этой функции не даёт побочных эффектов, то вызов чистой функции взаимозаменяем с его результатом (ссылочная прозрачность). 

<details>
<summary><b>Примеры, почему эти свойства не так очевидны, как кажется</b></summary>

Предположим следующую функцию на C++:

```cpp

// В нормальном коде это было бы классом, разумеется.
int balance = 0;
// Зачисляем amount денег, результат функции — сколько зачислилось
int storeMoney(int amount) {
    balance += amount;
    return amount;
}

...

// Два раза зачислили деньги
int stored = storeMoney(100) + storeMoney(100);

// Нельзя заменить на
int stored = 100 + 100;

// Потому что меняется смысл программы, хотя результат не меняется
```

Так же есть функция взятия случайного числа

```cpp

// Случайное целое число в полуинтервале [0; RAND_MAX]
int a = rand();

// Нельзя заменить на результат, потому что нету детерминированного результата
int a = ???;

```

Более сложный пример:

```cpp
// Берет вектор, вставляет перед pos значение value, возвращает интератор на созданный элемент
iterator std::vector<T>::insert(const_iterator pos, const T& value);

std::vector<int> v;
auto it1 = v.insert(v.end(), 1);
auto it2 = v.insert(v.end(), 1);

// it1 и it2 это разные итераторы!
```
</details>

Отсюда естественным образом следует предпочтение к неизменяеым значениям. Иначе если б значению было позволено быть изменяемым, то ссылочную прозрачность обеспечить становится сложнее. А отсюда уже приходит осознание, что "выражение предсказуемее последовательности инструкций над изменяемыми данными". Если значение никогда не меняется, то разработчику не надо отслеживать его изменения:) 

При этом не каждая функция является чистой и не каждое значение является неизменяемым. Функциональное программирование пропагандирует минимизацию т.н. _грязных_ функций.

Haskell предоставляет богатую стандартную библиотеку функций. Разработчик может определять новые функции как композиции уже существующих функций (в том числе и из определённых ранее). И в целом, программу можно рассматривать как очень сложную функцию. 

Функцию в Haskell можно определить интуитивным образом — `<name> <arg1> <arg2> ... = <expr>`. В качестве результата здесь можно указывать вызовы существующих функций в том же формате `<name> <expr1> <expr2> ...`. Есть и более сложные варианты определения функций, но о них дальше.

Пример функции, которая проверяет, является ли длина строки чётной: 

```haskell

-- even x   стандартная функция, которая принимает целое число x и возвращает True, если оно чётное или False, если нечётное.

-- length s стандартная функция, которая принимает список (строка есть список символов) и возвращает её длину

isLengthEven s = even (length s)  -- вызываем length s и передаём её результат в качестве аргумента `even`
```

Соответственно `isLengthEven "abc"` вернёт `False`, а `isLengthEven ""` вернёт `True`. Замечу, что это лишь базовый способ определять новые функции. По ходу документа будут показаны другие способы. В целом, любая программа на Haskell это сложная функция.

Помимо функциональных языков существуют императивные языки. Для них основная единица кода это инструкция, которую надо выполнить. И программа есть последовательный набор инструкций, которые читают/изменяют состояние программы.

Императивные языки противопоставляются функциональным. Про первые можно думать в контексте "как сделать", про вторые — "что сделать". Для более наглядного примера можно рассмотреть задачу нахождения суммы первых `n` натуральных чисел. Для императивных языков естественным считается путь:

* Создай переменную `res` с начальным значением `0`
* Создай переменную счётчик `i` с начальным значением `1`
* Если `i` больше, чем `n`, то верни `res`
* Иначе прибавь `i` к `res` (изменяем `res`) и прибавь к `i` единичку
* Перейди к третьему пункту.

Это конкретная последовательность действий, которые надо выполнить. Для функциональных же языков естественный путь:

* Пусть искомая функция это `sumFromOneTo(n)`
* Тогда `sumFromOneTo(0) = 0`
* А `sumFromOneTo(i) = sumFromOneTo(i - 1) + i`

Это можно записать так:

```haskell
sumFromOneTo 0 = 0
sumFromOneTo i = sum (i - 1) + i
```

Тут вводится функция с описанием "чему равен результат функции для тех или иных аргументов" и она считается. Никаких изменяемых значений, никаких последовательностей инструкций. Только математическая функция.

#### Компилируемость языка.

Код на Haskell преобразовывается специальным инструментарием в набор машинных инструкций, который будет понятен компьютеру. На выходе получается готовый исполняемый файл (запускаемая конечная программа) или объектный файл (библиотека, которую можно подключать к другим исполняемым файлам) в зависимости от кода.

Компилируемым языкам противопоставляются интерпретируемые языки. Это языки, для которых есть специальная программа (интерпретатор), которая исполняет команды по очереди. Интерпретатор уже скомпилированная программа, предоставляемая экосистемой языка. Как правило, на компилируемых языках получаются более высокопроизводительные программы (в первую очередь из-за того, что компилятор знает о всем коде и может делать более агрессивные оптимизации, а интерпретатор знает только о конкретной команде, которую исполняет в данный момент).

#### Статическая типизация.

В языках программирования так или иначе присутствует понятие _типа данных_. Под ним можно рассматривать именованное множество значений и операций над этими значениями. Для примера, тип "строка" — это последовательность (возможно пустая) символов и над ней практически во всех языках программирования определена операция взятия длины. Далее для языка программирования вводится понятие _типизации_ — как набора правил, как связываются между собой значения и типы, и как определять, можно ли применять операцию ко значению(ям). Если коде в программы попробовать к строке прибавить число 4, то как и в какой момент будет принято решение, что это некорректная операция?

В Haskell принята т.н. _статическая типизация_. Каждому выражению в коде на этапе компиляции будет сопоставлен некий тип. И если выяснится, что в коде есть применение недопустимой для этого типа операции (передача в функцию, которая ожидает аргумент другого типа или вызов функции, которая не определена для этого типа). То программа не скомпилируется и программист увидит соответствующую ошибку.

```haskell
isLengthEven s = even (length s)

-- incorrectFunction s = (isLengthEven s) + 2  Не скомпилируется, т.к. isLengthEven s это значение True или False, а операция + для True и целого числа не определена
```

Альтернативой для статической типизации является _динамическая типизация_. Тут правила такие, что тип у значения определяется непосредственно во время исполнения программы. Как следствие, ошибки, связанные с некорректными операциями, проявят себя только во время исполнения.

#### Сильная типизация.

Сильная типизация подразумевает сильный набор правил касательно того, можно ли делать попытки неявного преобразования значений к правильным типам. Рассмотрим пример выше. Там код не скомпилируется из-за того, что есть попытка сложения True/False с двойкой. Сильная типизация говорит, что попыток воспринимать True/False как число или двойку как True/False предпринимать не надо. Будь Haskell язык со слабой типизацией, то код бы скомпилировался бы, и incorrectFunction была бы вполне валидной функцией, просто с неочевидным принципом работы. Еще пример сильной типизации тут: 

```haskell

x::Integer  -- объявляем переменную x типа Integer (произвольное целое число)
x = 2

y::Double   -- объявляем переменную y типа Double (вещественное число)
y = 2.5

-- f = (x == y) (проверка на равенство) тут будет невалидной операцией, потому что x и y имеют разные типы, а сравнение определено только для значений одного типа

```

Обычно к языкам с сильной типизации относят и языки, которые разрешают складывать целые и дробные числа. Потому что это ж валидно так делать, с т.з. математики, почему это должно не работать? Но Haskell отрицает подобное: хочешь сложить два числа — убедить, что они имеют одинаковый тип.

#### Ленивость.

Под ленивостью подразумевается свойство откладывания вычисления функций до последнего. Никакое значение не будет вычислено, пока не будет установлено, что это значение _необходимо вычислить_. Для примера:

```haskell

veryLongFunction x = ...                             -- Что-то выполняющееся очень долго

veryShortFunction x = ...                            -- Что-то выполняющееся очень быстро

solve x = (veryLongFunction x, veryShortFunction x)  -- Что-то, возвращающая пару (со стороны кажется, что нужно вычислять оба значения)

func x = snd (solve x)                               -- snd это стандартная функция, принимающая пару  и возвращающая второе значение.

```

Для вычисления `func x` не будет считаться `veryLongFunction`, потому что оно не нужно. Еще один пример ленивости — бесконечные структуры данных. Можно объявить бесконечный список, но это не значит, что он будет в действительности существовать и тратить память. Более подробно это будет описано в главе про ленивость.

#### Чистота Haskell.

Вот и добрались до важнейшего свойства Haskell. Выше было дано определение чистой функции и указано, что функциональное программирование предполагает минизацию грязных функций в коде. Haskell тут ушёл дальше и декларирует, что все функции являются чистыми (за единственным исключением, о котором в главе про IO). Поэтому говорят, что Haskell не просто функциональный язык, а чисто функциональный.

Читатель может спросить "То есть там нельзя запрограммировать обработку пользовательского входа? А зачем тогда это всё?". Ответ: можно. Как именно это работает, будет разобрано в главе про IO.

#### В примере с сильной типизацией есть строка `f = (x == y)`. Будь одинаковые типы у значений `x` и `y`, чем бы конкретно являлось `f`?

<details>
<summary><b>Ответ</b></summary>

`f = (x == y)` подходит под синтаксис `<name> <arg1> <arg2> ... = <expr>`, так что `f` тут является функцией без аргументов, чьё значение это `True` или `False`, в зависимости от значений `x` и `y`.
</details>
